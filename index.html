How I work

I build with Claude Code and a set of skills I've set up for each stage of a project, so planning, testing, review and design checks happen every time, not when I remember.

  1. 1

    Plan

    Questions first, then a written plan with the tools for each step, approved before any code.

    Brainstorming, writing plans

  2. 2

    Test first

    A failing test before every fix: unit tests, database tests and browser checks.

    Vitest, pgTAP, pytest, Playwright

  3. 3

    Review

    A security audit and a code review on the change, with every finding traced to a line of code.

    Security audit, code review

  4. 4

    Design checks

    Screenshots at desktop and phone width, contrast, keyboard focus and reduced motion.

    Design audits, accessibility sweeps

  5. 5

    Ship

    Nothing is called done until the real commands pass and the output says so.

    Verification before completion

On PG Manager this caught six security issues before launch, from a manager being able to delete payment history to a tenant permanently discounting rent. Each one now has a database test that fails if it comes back.

I also build tools for this way of working: DevPilot MCP lets an AI read and change a repository only through approved, logged steps.
